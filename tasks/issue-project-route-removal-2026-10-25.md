# Issue / Project 路由删除与加载优化

## 当前结果和边界

Web、Desktop、Mobile 的 `issues`、`projects`、`my-issues` 路由族已退役，列表、详情与移动端创建/选择页面已删除。工作区默认落点统一为 chat；旧 URL 不增加重定向。退役 slug 继续保留，桌面持久化的旧标签及前进/后退目的地会被丢弃。

**这不是整个后端领域的完整删除。** `server/cmd/server/router.go` 的 Issue / Project API、CLI 命令、旧自动化 `create_issue` 模式及部分内部任务模型仍存在；自动化配置仍保留 Project 上下文。原始完整功能删除方案中的生产者停止、API/CLI/工具契约删除和领域依赖清理尚未执行。本轮不删除历史表、附件、聊天记录或执行记录，也未部署。

## 已实施

- 删除 Web 的 issues/projects 列表和详情路由、Desktop 对应注册及页面包装，删除 Mobile 对应页面、创建页、picker 和原生任务搜索页。
- 删除侧边栏旧入口与收藏树、旧全局创建/跳转快捷键、搜索中的 Issue / Project 结果与创建命令、全局旧业务弹窗挂载和 Issue 独立桌面窗口及 IPC。
- Agent / Member 页面不再挂载任务面板；保留任务运行历史的页面不再提供通往已删除详情页的链接。
- 聊天主页面不再读取项目列表或提供项目选择，创建会话不再提交持久化的旧项目选择；附件、草稿、发送与队列行为保留。编辑器不再向服务器搜索 Issue / Project 提及或自动解析任务编号。
- 设置移除任务状态、属性、唤醒、快捷动作和创建偏好入口；标签管理保留 Skill 作用域；通知设置保留系统通知。
- 收件箱仅保留无 `issue_id` 的 `autopilot_paused` / `autopilot_quota_exceeded`。前端和 Mobile 过滤旧任务、quick-create 及 children_done；实时任务通知不再触发系统通知或新条目刷新。
- 服务端列表、单条读取、归档分页、筛选统计、未读摘要和已读/归档操作使用相同系统通知范围；读取不再关联 Issue 状态/优先级。`make sqlc` 已重新生成。
- 全局 Provider 不再启动完整 Issue / Project 搜索索引同步；侧边栏移除旧收藏、视图和对象查询；搜索成员查询仅在打开并输入后启用；标签标题移除任务/项目缓存观察和状态目录观察，不再恢复旧收件箱属性筛选。
- Web lint 忽略 `.next-local/`，避免把本地生产构建产物当源代码扫描。修复前全量扫描产生约 5 万条产物错误；修复后五个客户端/共享包 lint 均为零错误。

## 构建体积

口径：相同 Next webpack 生产构建下，对每个页面客户端引用清单与 rootMainFiles 的 JS 去重，统计文件长度及逐文件 gzip 后长度。**包括延迟加载模块，不代表首次实际下载量、LCP、INP 或提速百分比。** 前段基线的数值来自本轮删除前的实际构建；临时日志被环境清理后已将这些记录重新归档为 `bundle-before.json`。

| Chat | 1,951,854 B | 1,727,438 B | 11.50% | 73 → 69 |

脚本和原始记录位于 [verification/issue-project-removal-2026-10-25](verification/issue-project-removal-2026-10-25)。最终构建已记录 1,553 个输入文件的 SHA-256；构建期间无输入变化，构建路由清单不存在三个退役路由族。

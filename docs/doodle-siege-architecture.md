# Doodle Siege 架构

当前宿主、存储、加载与验证规范见 [Siege 工作区集成](siege-integration-plan.md)。Siege 与坦克守城是平级的工作区功能，分别拥有规则和运行时。

## 领域与编译

`packages/core/siege` 定义 Drawing、WeaponSpec、参数炮台、几何与编译结果。模型只提出部件标注，不能提供伤害或执行代码；手动标注无需 AI。编译器验证笔划引用、连接、安装点、炮口与朝向，按版本化尺寸确定性地产生碰撞几何及性能。

参数炮台和自由绘制草稿分开保存。保存的蓝图携带规则版本与原画，未知版本仍保留原画，重新确认后才进入当前运行时。部署复制并冻结蓝图，编辑不会改变已部署实例。

## 战斗与绘制

`packages/views/siege/runtime` 实现工坊试验场，`campaign` 实现多炮台战役。两者复用物理初始化与编译结果，保留独立胜负和波次规则。Rapier 与 DOM 留在 views；路径、选敌、定价与存档校验留在 core。

模拟固定 60Hz，炮弹使用真实碰撞和 CCD，近战根据接触与目标冷却结算。所有波次和援军生成且活敌清空后才获胜。敌人、炮弹、特效与事件均有容量上限，满额延后生成，不静默丢弃敌人。

Canvas 使用共享原画，静态场景与原画路径缓存。React 展示低频 HUD 与可访问操作，不保存物理世界。准备、暂停、结算停止连续绘制；页面隐藏与窗口失焦暂停。

## 数据与 API

`server/internal/siege` 挂在主服务的工作区成员路由中。会话以 PostgreSQL JSONB 原子保存，幂等请求与 expectedVersion 保证安全重试和冲突反馈。识别回执记录不确定结果，恢复回执不会重复调用模型。

个人本机进度按账号和工作区 UUID 隔离；蓝图库由服务端权限控制。战斗成绩仅本地保存或由玩家主动导出，不作为权威排名。

普通与识别模式、Web/Desktop 构建、认证 E2E 及 PostgreSQL fixture 测试均走主项目流程。

# DEAL V0.1 产品需求文档

状态：已按 2026-10-06 用户确认范围实现，本地规则试玩与模型模拟契约验收通过。真实模型语义质量与玩家体验另行验收。
来源：[原始构想](ai游戏方案20261006.md)。

## 1. 产品与目标

DEAL 是独立的谈判游戏，使用独立 `/deal` 路由，不需要 Auro 账号、工作区或智能体运行环境。按需复用仓库的 React、UI、API 校验与 Go 模型调用基础能力。第一版是文字输入、角色反应与物品操作，语音后续接入。

玩家欠 Victor $100,000，身上只有 $3,000。Marco 前来收债。玩家通过提问、观察、证据、诈唬与协议改变局势。核心循环是观察 → 表达 → 反应 → 发现 → 调整策略，玩家看不到心理数值。

目标：陌生玩家能够通过反馈建立对手的心理模型，使用信息改变策略，理解结局原因，并愿意尝试另一条路线。技术通过不等于玩法验证通过。

## 2. 第一版范围

- 一个房间，一个固定人物 Marco，一套版本化关卡。
- 自由中文文字输入，支持常见英文表达；不提供预设对话选项。
- 八件物品：现金、银行账单、手机、Victor 合照、业务合同、车钥匙、Marco 口袋里的旧照片、Marco 的信封。查看旧照片后才知道 Sofia 的身份。
- 角色姿态、视线、动作描述、字幕；不做 3D、STT、TTS、多 Boss 或成长系统。
- 四个结局：延期、胁迫放行、合作、失败。原始十个结局作为后续目标，首版不展示不可达成的结局。
- 存档恢复、重复请求保护、结局复盘、重开、复盘文字下载。
- 配置模型后使用 AI 理解自由表达。无模型时显示配置状态；规则试玩是操作者显式选择的独立模式，不自动替代 AI，不作为真实模型验收证据。

## 3. 关卡事实与资源

1. 欠款 $100,000；现金 $3,000。交付现金后欠款变为 $97,000，现金不可重复使用。
2. 银行账单证明当前流动资金不足；展示只改变 Marco 的判断，不产生资金。
3. 合同是已签署的 $128,000 应收款，三天后到期；手机中有对方联系方式。Marco 核实后才算可信还款来源。
4. 合照证明玩家认识 Victor，同时引起 Marco 对组织关系的警惕。
5. Marco 偷了 $42,000，害怕 Victor 发现；Victor 目前怀疑，尚未掌握完整证据。
6. 信封内有收款账目与备用护照。玩家取得查看机会才能知道细节；猜中金额允许诈唬，但不会自动获得证据。
7. Sofia 是 Marco 的女儿。她的安全是红线。照片透露关系，不开放对她采取现实行动。
8. Marco 想获得合法收入、减少对 Victor 的依赖。合作可以利用合同结余设立 $8,000 合法佣金，不需要虚构立即获得 $80,000。
9. 车钥匙只证明持有钥匙，不证明车辆所有权，不能单独当作抵押。
10. 手机备份是关卡内动作，只能备份已获得的账目证据；不访问或发送真实外部信息。

## 4. 用户故事与验收

下列完成项以代码、规则测试、模型模拟服务与本地浏览器为证据；具体命令见[交付记录](deal-delivery.md)。它们不代替真实模型或陌生玩家验收。

### US-001：进入独立游戏
作为玩家，我希望直接进入 `/deal` 并开始游戏，不经过团队产品的注册与工作区流程。
- [x] 首页显示债务、处境、开始按钮、可恢复存档和模型模式。
- [x] 开始后进入房间，Marco 给出开场要求。
- [x] 刷新可以恢复同一局；重开必须经确认，不覆盖原局记录。
- [x] 在浏览器验证（使用可用的浏览器控制工具；本环境没有 dev-browser skill）。

### US-002：自由表达与可读反馈
作为玩家，我希望用自己的话提问、试探、提出条件，看到相关反应。
- [x] 输入与回复有明确提交、等待、失败与重试状态。
- [x] 等待期间不能并发提交；失败保留原输入与请求标识。
- [x] 显示 Marco 姿态、动作、台词；不显示 trust/fear 等内部数值。
- [x] AI 误格式、超时或拒绝不提交游戏状态，不扣剧情时间。
- [x] 在浏览器验证键盘操作和窄屏布局。

### US-003：操作物品与发现信息
作为玩家，我希望查看、展示、交付或备份物品，用具体证据影响谈判。
- [x] 查看自己物品不推进剧情时间，也不自动让 NPC 看见内容。
- [x] 展示、交付、备份和搜查是服务器确认的动作。
- [x] Marco 的私人物品只能在他离开核实合同的短暂机会中搜查；一次机会只搜查一件，随后他返回；也可选择等待返回，放弃搜查。
- [x] 展示同一证据、重复搜查或反复说同一句话不能刷心理收益。
- [x] 没有证据时可以诈唬；不能凭一句话增加物品或资金。
- [x] 在浏览器验证可用与不可用操作及其原因。

### US-004：声明、矛盾与圆谎
作为玩家，我希望对手记住我的关键说法，并允许我解释矛盾。
- [x] 声明引擎区分资金现状与未来承诺；结构化抽取限制问题、条件与否定表达产生当前资金断言。
- [ ] 正式模型对中文自由表达中的时态、条件、否定与问题识别通过真实语料回归。
- [x] 声明包含原句、命题、时间/范围和来源；信念依据可追踪。
- [x] “没有现金”和“未来能还钱”不是直接矛盾。
- [x] 相同时间和范围的相反说法触发追问；合理范围澄清能够解决矛盾，不能抹去历史。
- [x] Marco 的秘密不会因模型收到玩家指令而泄露。

### US-005：达成有因果的结局
作为玩家，我希望通过可验证的策略完成关卡，知道结果为什么发生。
- [x] 延期：账单展示、合同经核实、现金交付，玩家提出三天内偿还余额，Marco 给出条款，玩家明确接受。
- [x] 胁迫：账目已取得、手机已备份、曝光威胁建立可信杠杆，玩家提出保密换放行，Marco 给出条款，玩家明确接受。
- [x] 合作：合同经核实，Marco 的离开动机已被发现，尊重/信任及目标条件满足，玩家提出合法合作，Marco 提出合同结余佣金方案，玩家明确接受。
- [x] 失败：剧情时间耗尽、持续越过女儿安全红线，或愤怒/怀疑达到危险条件并执行强制行动。
- [x] 结局必须由引擎确认协议或行动，不能由台词直接触发。
- [x] 结束后禁止继续操作；复盘列出关键行为、发现、未兑现声明和因果事件。
- [x] 在浏览器验证完整胜利与失败路线、重开及复盘下载。

## 5. 功能要求

- FR-01：独立 Web 应用入口 `/deal`，使用独立会话与匿名浏览器所有权，不绑定 workspace/issue/task。
- FR-02：每局固定关卡与规则版本；六项情绪、对玩家/对 Victor 的恐惧、忠诚与离开动机分开存储。
- FR-03：AI 只抽取结构化意图/声明，并从引擎授权的对白中选择表演，不能直接提供属性增减或世界写入。
- FR-04：未知话题允许继续交流，但不凭空生成可执行的世界行动。
- FR-05：心理更新必须有命题、证据或上下文依据；重复输入收益递减至零。
- FR-06：模型调用输入不包含完整秘密表；允许的对白由引擎根据知识和行动挑选。
- FR-07：每个回合带请求 ID 和期望版本，失败不改状态，同请求同内容重试不重复执行，并返回包含已提交结果的最新存档；不同内容复用 ID 拒绝。
- FR-08：会话快照和实际回合结果持久化，服务重启后可继续与复盘。
- FR-09：客户端仅收到玩家可观察的状态；秘密、信念、规则阈值和所有权凭证不可泄露。
- FR-10：首版采用 8 分钟剧情时间：谈判、展示、交付、备份、搜查和等待 Marco 返回，每次消耗 20 秒；查看自己物品不消耗，模型/网络等待不计时。最多 24 次推进动作；每局总操作记录上限 96 条。该规则通过帮助明确告知。
- FR-11：可恢复的服务错误保留输入并支持重试；身份、资源和版本冲突使用独立错误码。
- FR-12：初版界面为简体中文；游戏品牌保留 DEAL。语音、多语言整套体验、随机关卡和公共分享平台后续实现。

## 6. 设计要求

暗色室内光、桌面物件、Marco 居中近景；字幕与输入是主要控制区。姿态是反馈的一部分，动作描述保证信息不依赖动画。使用现有 UI Button 与语义字号；键盘焦点清楚，状态不仅靠颜色，尊重 reduced-motion，窄屏可以滚动。

不要展示内部策略标签或诊断日志作为玩家 HUD。配置、模型模式、隐私和时间规则放在入口或明确帮助中。规则试玩必须可识别。

## 7. 成功指标与验证边界

开发验收：四条结局路线可达；资金不重复交付；矛盾可追问/澄清；模型失败不扣时；注入不能改事实；授权隔离；重复请求、重启恢复和复盘均通过检查。

陌生玩家首测：观察是否发现反应、使用证据、切换策略，并能解释策略因果。记录完成局数、立即重玩、每局有效动作、秘密发现、分享意愿与模型等待。10 人用于发现问题；35% 重玩、50% 使用两种策略等是待验证产品目标，不能当作已证明的行业基准。

真实模型语义质量、延迟、成本、陌生玩家体验与公开部署分别验收。规则模式或模型模拟服务通过，不代表真实模型通过。

## 8. 后续与开放项

后续接 STT/TTS 时保持文字输入、回合引擎与事件模型，语音只改变输入输出。付款、逃脱、逃亡、KINGMAKER、新人物与关卡变体需另行补齐资源和行动链。

开放项：正式模型配置、公开试玩访问与预算策略、美术升级、真人试玩结果。它们不阻塞本轮本地文字版开发，但未验证前不得宣称公共发布或玩法指标达成。

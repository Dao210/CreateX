# 本机性能优化验收（2026-10-25）

本批优化已实现，并已将本机 `http://localhost:13440` 切换为托管生产模式。后端继续使用端口 18520 和原数据库 `auro_createx_440`。环境已登记为持久的人工作业环境，取消旧的自动回收期限；`make status` 可核对前后端进程归属及 Web 运行模式。

## 已完成的改动

- 公共布局中的创建弹窗、搜索、浮动聊天改为按需加载；来源补填弹窗先判断用户是否需要，再加载内容。
- 关闭浮动聊天时卸载消息、编辑器和查询订阅。轻量入口继续维护未读和任务状态，上传仍由已有独立协调器管理。关闭、重开及刷新恢复均已验证。
- 实时聊天生命周期在 100ms 窗口合并同一查询的刷新；慢请求不再被新事件反复取消，期间发生的变化保留一次后续刷新。跨会话任务汇总使用独立的 750ms 合并窗口，继续从服务端获取权限过滤后的结果。
- 编辑中的草稿即时更新内存，持久化合并到 300ms 后。程序恢复草稿仍即时写入；切换会话、关闭、发送、页面离开和工作区切换时完成保存。注销或删除工作区会取消待写入内容，避免旧草稿被延迟写回。存储写入失败的内容保留到下一次保存机会。
- 编辑器在卸载前提交尚在防抖窗口内的文字，避免关闭聊天时丢失最后输入；没有为此增加逐键完整序列化。
- 日志默认仅输出 warn/error；Web 的 `NEXT_PUBLIC_AURO_LOG_LEVEL=debug`、桌面的 `VITE_AURO_LOG_LEVEL=debug` 可显式开启详细诊断。
- 单独启动 Web 开发服务时直接调用 pnpm，移除持久 Turbo 中间进程。新增托管生产模式，使用独立 `.next-local` 目录，通过源码和构建配置指纹判断是否需要重新构建；构建期间源码变化时拒绝把产物标记为可用。
- 聊天窗口图标按钮使用现有翻译作为可访问名称，浏览器可按名称验证最小化及重新打开。

## 后续使用

```bash
make status
make up MODE=production
make up MODE=development
make down
```

默认 `make up` 会沿用已选的 Web 模式。`make down` 保留数据。修改源码后重新执行 `make up MODE=production`，生产模式会检查并重建过期产物。开发时使用 `MODE=development` 保留热更新。

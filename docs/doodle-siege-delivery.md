# Doodle Siege P0 开发交付与验收

日期：2026-10-07。依据：[产品构想](画武器对战20261007.md)、[技术方案](doodle-siege-architecture.md)。

## 已实现的闭环

独立 `/siege/` 游戏已实现：鼠标或 Pointer Events 画图 → 手动标注或视觉识别提议 → 修正部件与转轴 → 确定性编译 → 真实 Rapier 碰撞测试 → 根据命中、负载、范围与失败反馈重画。原始笔画随刚体移动，碰撞范围可以显式显示；草图保存在 IndexedDB，蓝图保存在独立 Go 服务，支持刷新恢复、PNG 原画与 JSON 蓝图下载。

当前支持刀刃、锤头、火炮、轮轴、盾牌，另有被动连接结构。每件最多四个功能部件、一个安装轴；同一装配焊接到一个刚体，轮轴配主动部件时旋转，无轮轴的主动部件摆动，盾牌保持被动。驱动力有上限，质量、质心、惯量、覆盖范围与墨水从几何计算，模型不能指定伤害或物理参数。悬空笔画、自交或凹形闭合轮廓、重复引用、超预算和过度复杂的线条会保留画图并提示修改。

除 20 秒测试场，另有一个安装位、固定三波敌人的守城试玩，包含普通目标、重目标、城堡血量、盾牌耐久与失败反馈。它用于比较设计差异，仍属于 P0。八种部件、三个安装位、关卡成长、公开作品、可信排名与原生发行属于后续范围。

地图、城堡三种状态、敌人行走帧、战斗特效、装饰和工坊纸纹共三十张素材，已通过内置浏览器 ChatGPT 网页生成并接入展示层。来源文件、提示词、裁切清单、导出脚本及本次验收见 [素材包与复用](siege-art/README.md)。

## 自动炮台与数值面板（2026-10-08）

规则版本为 `p0.2`。增加“自动炮台”示例和“火炮”部件。手动标注炮管后，在画布上设置炮口，再在炮口前方设置朝向；炮口与朝向有独立标记，不改写原始笔画。炮口必须位于炮管前端，炮管长度至少 0.4 m 且至少为宽度的 1.5 倍。首版只有一座炮台，可组合轮轴、连接结构、盾牌，暂不与刀刃或锤头组合。

自动选择可射击范围内最接近城堡的敌人；保留目标直到目标离场、死亡或不再可射击，同位置按稳定 ID 排序。转向通过有界力矩和目标角速度驱动真实刚体，考虑炮口相对转轴的偏移。提前量最多迭代两次并限制预测时间。瞄准偏差不超过 3°且装填完成后自动开火；实心弹以有限弹速直线飞行，命中造成伤害与击退，不追踪飞行中的目标。

确定性编译器根据炮管长度、横向宽度和整体惯量计算射程、弹速、弹丸直径、基础伤害、装填步数及最大目标追踪速度。示例炮台为 52 / 100 墨水、7.1 m 射程、24 HP 基础伤害、1.52 s 装填、58.6°/s 最大追踪速度；精确装填时间为 91 / 60 s。重目标炮弹伤害系数为 0.6。墨水用于建造，不按发射次数扣除。AI 仅提议部件、炮口、方向和连接，严格响应校验拒绝模型指定伤害等执行参数。

炮弹使用真实 Rapier 动态圆形碰撞体、CCD 和碰撞组，与敌人碰撞，排除自身炮管和其他炮弹。每发只结算一次，达到射程、寿命或场外边界就释放，场内最多 24 发；重新测试和卸载时释放整个物理世界。弹丸与炮口闪光通过 Canvas 绘制，命中特效复用既有素材。

“设计参数”显示当前草图编译结果，按武器种类显示墨水、质量、覆盖／射程、伤害、装填、追踪速度和盾牌初始耐久；详细参数折叠展示弹速、弹径、理论射速、惯量和相对转轴的质心。质量与惯量使用游戏单位，刀锤不显示固定每击伤害。炮台基础伤害针对无护甲目标，理论射速假设持续瞄准。

“实时数据”只读取启动时冻结的武器副本和物理引擎统计，显示目标距离、瞄准偏差、装填进度、发射、命中炮弹、命中率、实际总伤害、击败、击退离场、时间、实际转速和相应的城堡／盾牌生命。命中率分母是所有已发射炮弹，仍在飞行的炮弹暂未命中；实际伤害按实际扣血累计，排除过量伤害。战斗计数在 60Hz 物理步中更新，界面约每 120 ms 采样；暂停冻结世界和全部实测值，结束后保留结果。

修改草图、部件、转轴或炮口后，左侧更新设计，右侧保留本次测试，并提示“设计已修改，重新测试后生效”。旧规则蓝图仍保留原画，需重新确认部件后按当前规则测试；未增加旧规则执行适配、存档数据库或成绩上传。

## 精制炮台工坊（2026-10-08）

首次进入默认展示“林地守卫炮”；“精制炮台 / 自由绘图”切换分别保留草稿与名称，刷新恢复当前模式。现有 IndexedDB 原画草稿仍在自由绘图中恢复。精制炮台不依赖 AI 配置：长度 1.60–3.20 m、管体宽度 0.45–1.05 m，以 0.05 m 步进，支持滑杆、键盘、数值输入和恢复默认。输入确认时限制在允许范围并对齐步长；429 种组合均通过编译、连接、材料预算与炮口位置检查。

炮管长度与粗细生成真实 Drawing、部件、轮轴、炮口和朝向，继续由既有编译器计算质量、惯量、射程、弹速、伤害、装填与追踪速度。设计面板的增减值与默认炮比较。本次守城冻结参数和几何；调节当前设计后提示重新开始，暂停与结果仍保留当前战斗。默认炮约为 53 / 100 墨水、24 HP 伤害、7.1 m 射程、1.52 s 装填与 57.0°/s 最大追踪速度。

炮台采用同一 Canvas 分件绘制函数供预览、战场及 PNG 导出使用：固定装饰石座、圆形转动轴、炮尾滑块、森绿金属管身、黄铜炮箍与炮口。尺寸来自同一量化几何；调整管身时，炮箍和炮口保持自身比例。开火复用烟雾素材、炮口闪光，视觉后坐只移动炮尾内部滑块，保留实际炮口与轮廓位置；减少动态效果设置关闭后坐。

蓝图 API 增加可选 `cannonDesign`，记录 `cannon-kit`、部件版本 1 和毫米整数参数。浏览器草稿以参数为预设炮的唯一编辑输入，生成几何不独立编辑。保存蓝图保留现有 Drawing/Spec 契约，Go 服务校验参数范围及生成几何、部件定义的一致性，再使用原有幂等保存与所有权机制。core 与 Go 共用一份几何契约 fixture；旧蓝图缺省元数据仍作为自由绘图读取，未来或损坏的元数据保留原画。

守城胜利条件改为十五名敌人全部出场、剩余敌人处理完且城堡存活；不再以 45 秒自动判胜。城堡生命归零立即失败，实测显示已出场、剩余敌人及胜负。火炮、轮轴及连接杆的接触范围在炮台模式中作为传感器，敌人可穿过炮管继续向城堡前进；盾牌仍承担实体格挡与耐久，避免炮管把无法射击的近身敌人永久堵住。保持一个安装位、三波固定进攻。

本次验证：core Siege 16 项单测（含全部参数组合、几何契约、真实性能变化、响应兼容）；Siege 10 项单测（含 45 秒后仍有敌人的回归、提前失守、五组尺寸在真实 Rapier 中完成守城）；typecheck、目录 lint、正式构建；Go siege/cmd/siege/llm 的 race 与 vet；8 项 Playwright 对显式 fixture 的同源正式构建验收。浏览器验证保存/刷新恢复、草稿隔离、键盘调节、暂停冻结、改装后的重开与无 AI 配置时可直接守城，另有 1280px 桌面和 390px 窄屏视觉检查。未增加依赖，未调用真实模型或外部部署。

## 运行与模式

```bash
pnpm install --filter @auro/siege... --frozen-lockfile
pnpm --filter @auro/siege build

# 明确使用固定样例识别，不调用真实模型
SIEGE_RECOGNITION_MODE=fixture make up C=siege
make status C=siege
make down C=siege
```

开发入口：`http://127.0.0.1:13107/siege/`。同源正式构建：`http://127.0.0.1:18107/siege/`。数据在 `.siege/sessions/`，日志在 `.siege/logs/`；停止保留数据，不停止其他游戏。已经启动时 `up` 只检查状态；修改模式后先停止再启动。

默认 `SIEGE_RECOGNITION_MODE=llm`。未配置时 AI 按钮不可用，手动标注、测试与存档仍可使用。固定样例模式仅识别原封不动的旋转锤和自动炮台样例，自由画图使用手动标注；界面明确显示模式，不把规则识别显示成真实 AI。

真实模型使用根目录被忽略的 `.env.siege` 或环境变量：`SIEGE_LLM_API_KEY`、可选 `SIEGE_LLM_BASE_URL`、`SIEGE_LLM_MODEL`、`SIEGE_RECOGNITION_MODE=llm`。型号必须同时支持图像与严格 JSON Schema，本次未推荐或验证具体型号；不会读取 Auro 的 `.env` 或隐式复用其凭据。模型收到服务端从 Drawing 重绘的 512×512 PNG、草图 hash，以及有界笔画 ID、点数、边界与端点元数据。没有外部图片 URL、生成代码、原始坐标全集或战斗成绩上传。

独立部署可设置 `SIEGE_LISTEN_ADDR`、`SIEGE_ASSETS_DIR`、`SIEGE_DATA_DIR`。HTTPS 代理保留原 Host，并设置 `SIEGE_SECURE_COOKIES=true`。文件存储只支持同一目录一个进程，当前启动与存储实现验证于 macOS；CI 为 Linux，不承诺 Windows Go 服务或多副本共享写入。

## 恢复与资源边界

识别使用 `requestId + drawingHash` 收据；同 ID、同画图返回原结果，不再次调用模型。同 ID 换画图拒绝。响应丢失时读取收据，结果不明时保留预算；只有玩家再次点 AI 识别才创建新请求。旧 hash 或旧 revision 的结果不能覆盖新草图。蓝图保存使用独立请求 ID 与 `expectedVersion`，响应丢失后的原请求重试不会新增第二份蓝图；版本冲突刷新清单并提示。

每次模型任务含并发槽等待共 8 秒，最多两个同时调用，SDK 自动重试为零；同一会话处理中的其他写入或收据读取返回忙碌，避免无限等待队列。全局 UTC 日预算默认 100，最大可配置 10,000；预算在调用前落盘，重启不重置当天额度。每会话最多 100 次识别、10 份蓝图，每所有者最多 5 个会话，全局最多 500 个会话。单个存档文件最多 16MiB，整个数据目录最多 128MiB。单次 JSON 请求最多 256KiB；原画最多 64 笔、总计 4,096 点。

文件写入使用临时文件、文件 sync、rename 与目录 sync，并由目录进程锁和会话锁保护。容量不足会明确报错，已保存蓝图保持原样。P0 不自动删除蓝图或识别收据，满额需显式扩容或归档；七天自动清理尚未实现。匿名 Cookie 只提供所有权隔离，接口还有有界的直接来源 IP 限速；公开反向代理部署需要再确定可信代理与限速策略。

碰撞只用圆、凸多边形与线段胶囊，最多 24 个。面积/质心/惯量使用固定网格近似；伤害是有限的游戏规则，尚未实现精细切割边缘、材料断裂或真实机械能标定。战斗在固定 60Hz 客户端步进，不存储中途世界快照，也不接受成绩排名。当前为俯视平面、零重力试玩，未来的侧视重力玩法需要另行调参和验收。

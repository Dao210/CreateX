# 坦克守城

坦克守城是 Auro 的一级工作区功能，与任务、项目及涂鸦攻城平级。Web 和桌面共用地图、规则与界面，沿用 Auro 的工作区身份、导航、标题、搜索和发布流程。

## 入口与启动

工作区侧栏直接点击「坦克守城」。正式页面路径为 `/{workspaceSlug}/tanks`，例如 `{AuroOrigin}/acme/tanks`。

- Web 入口：`apps/web/app/[workspaceSlug]/(dashboard)/tanks/page.tsx`，使用现有 DashboardLayout 和工作区校验。
- 桌面入口：`apps/desktop/src/renderer/src/pages/tank-defense-page.tsx`，挂在现有工作区路由与标签系统中。
- 路径、图标和标题通过 `packages/core/paths` 注册；全局搜索也可找到该入口。
- 页面标题和侧栏沿用 Auro 样式，复古像素画面位于游戏区域内。支持现有五种界面语言。

```sh
make up C=api,web
make status
```

在 `make status` 给出的 Auro 地址登录并进入自己的工作区。游戏随主站启动和构建；不需要 Siege 的独立进程、识别接口或 AI 配置。原 `/{workspaceSlug}/siege/tanks` 和独立壳 `/siege/tanks/` 已移除。

## 操作与规则

| 操作 | 键盘 | 触屏 |
| --- | --- | --- |
| 移动 | 方向键或 WASD | 按住方向按钮 |
| 射击 | 空格或 J，按住连发 | 点按或按住开火 |
| 暂停 / 继续 | P 或 Escape | 暂停 / 继续按钮 |
| 游戏全屏 / 退出全屏 | F，或全屏时 Escape | 页头全屏按钮 |

开始或继续后画布获取焦点。方向和射击键仅在画布聚焦时控制坦克，工具栏按钮保留自己的键盘操作。焦点移出游戏、打开全局搜索、页面隐藏或窗口失焦时自动暂停；继续后需重新按下操作键。

每张地图为 26 × 26 格，基地位于底部中央。生命、装甲和基地耐久始终显示在游戏区域内。生命耗尽或基地耐久归零即失败。

### 两个难度

默认选择「休闲」，开局前可切换；难度按账号和工作区保存在本机。换图、重试及战役推进沿用当前难度，进行中和暂停时不可更换，先「结束本局」再选择。

| 规则 | 休闲（默认） | 标准 |
| --- | --- | --- |
| 初始生命 / 上限 | 5 | 3 |
| 坦克装甲 | 角色装甲额外增加 1 点 | 角色原有装甲 |
| 基地耐久 | 3 次有效命中，受击后保护 1.5 秒 | 一次命中失守 |
| 自己的炮弹 | 不伤害基地 | 可摧毁基地 |
| 敌军速度 / 炮弹速度 | 标准的 72% / 75% | 原速 |
| 敌军射击 / 增援间隔 | 标准的 1.6 倍 / 1.5 倍 | 原间隔 |
| 同时在场敌军 | 比标准少 1 辆，至少 1 辆 | 按地图和模式规定 |
| 开场部署时间 | 标准的 1.5 倍 | 地图原设定 |
| 初始火力 | 至少 2 级 | 战役 1 级，街机 2 级 |
| 阵亡后的火力 | 保留 | 下降 1 级 |
| 受击后的保护 | 装甲受击后保护 1.5 秒 | 原有出生 / 道具护盾 |
| 击杀补给 | 每 2 辆 | 每 3 辆 |

难度只修改本局规则与运行时装甲，不改变角色编译蓝图或已冻结的角色版本；MCP 角色对局同样可以在开局前选择难度。

### 全屏

支持浏览器原生 Fullscreen API：点击页头按钮或按 F 放大战场，隐藏应用侧栏、选图和角色库，保留生命、装甲、基地耐久与暂停操作。退出按钮或 Escape 返回原页面并暂停，战斗、得分、倒计时和敌军状态不会重建。手机竖屏保留底部触控，横屏将方向键和开火按钮放在战场两侧。

浏览器不支持原生全屏时按钮禁用；请求被浏览器拒绝时显示重试提示。本机不保存全屏状态。

### 三种作战模式

- **战役推进**：六关连续防守，按地图递增敌军数量与同时在场上限，前两关开场有 3 秒部署时间；进入下一关保留生命、得分和火力。最后一关清空全部敌军后胜利。
- **90 秒突击**：任选地图，90 秒内击毁全部敌军。初始火力 2 级，增援间隔为战役的约 65%，同时在场上限增加 1 辆（最多 6 辆）。倒计时随暂停一起停止，时间耗尽则失败。
- **无尽防守**：任选地图，首波 8 辆，此后每波增加 2 辆，最多 24 辆；同时在场上限从 3 辆逐步增加至 6 辆，增援间隔逐渐缩短至约 1.2 秒。每波清空全部敌军后休整 5 秒并获得补给，进入第 3、6、9…波时恢复一条命（不超过当前难度的生命上限）。地形破坏和机关消耗在本局持续保留。

街机模式可以直接体验六张地图；只有战役通关会解锁后续战役关卡。作战中与暂停时禁止直接切换模式或地图；暂停后可选择「结束本局」，保留最高得分并返回准备状态。

### 火力与补给

- 1 级火力最多两发炮弹同时在场，2–3 级最多三发；满级火力击穿钢墙。标准阵亡下降一级火力，休闲保留。
- 每累计击毁 2 辆（休闲）或 3 辆（标准）敌军掉落一次补给，按「火力、护盾、火力、炸弹、基地加固」循环。补给优先出现在玩家附近可达的通路上，存在 25 秒，场上最多 3 个。
- 4 秒内连续击毁敌军，得分倍率逐次提升至 3 倍；补给固定加 250 分，不受连击倍率影响。炸弹只清除已经在场的敌军，不跳过未生成的敌军。
- 水域阻挡坦克，炮弹可以飞过；树林遮挡画面；冰面有短暂惯性。

### 战场机关

| 机关 | 行为与对策 |
| --- | --- |
| 爆炸桶 | 敌我炮弹均可引爆，半径 72 内清除砖墙，对敌军造成 2 点伤害、玩家造成 1 点伤害，能连锁引爆。虚线圈表示作用范围，护盾可抵挡伤害。钢墙和基地不受爆炸波及。 |
| 传送带 | 沿箭头以每秒 30 单位推动双方坦克，不改变炮口方向，不穿越障碍，可逆向操纵抵消。 |
| 脉冲电场 | 每 6 秒一轮：安全 4 秒、黄色预警 1 秒、放电 1 秒。每轮至多定身同一坦克一次，玩家 0.5 秒、敌军 1.5 秒；定身时仍可开火，护盾生效时免疫。 |
| 维修站 | 自动补回一条已损失生命并提供 3 秒护盾，每局每站一次；满生命时不会消耗。 |

机关在 core 中参与固定步长模拟，Canvas 绘制同一份状态；动画减弱不会改变机关时间或碰撞。以上参数经过规则与结构测试，真实玩家的胜率、时长和重复游玩体验仍需持续观察。

## 身份与本机记录

宿主注入现有 `StorageAdapter`。记录键为 `auro:tanks:{userId}:{workspaceId}`，两个 ID 均经过编码，使用稳定 UUID。只有当前账号和工作区均已解析，页面才会读取或写入记录；身份切换会重新挂载本局，避免旧战斗和旧记录写入新工作区。

最高分、解锁关卡、难度、音效开关保存在当前设备，其中最高分和解锁关卡会单调合并到个人云端进度；刷新会重新开始战斗，切回原账号和工作区可恢复对应本机记录。存储被禁用或记录损坏时仍可开始新游戏。

没有添加在线排名或服务端对战结果；`/{slug}/me` 展示的是客户端上报、按账号和工作区隔离的个人成就，不参与排名或奖励。旧试玩记录没有账号归属，不自动迁入新的记录空间，也不会删除旧记录。

## 模块边界与接口

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 地图与类型 | `packages/core/tank-defense/levels.ts`、`types.ts` | 地形、出生点、敌军名单、角色与输入类型 |
| 战斗规则 | `packages/core/tank-defense/engine.ts` | 固定步长、碰撞、射击、寻路、补给及胜负 |
| 记录校验 | `packages/core/tank-defense/preferences.ts` | 账号与工作区键、版本与范围校验 |
| 共享页面 | `packages/views/tank-defense` | 工作台页面、Canvas、键盘与触屏操作 |
| 基础音效 | `packages/views/common/game-sound.ts` | 坦克与 Siege 共用的合成音效 |
| 宿主入口 | `apps/web`、`apps/desktop` | 路由、工作区身份与存储适配 |

坦克模块不依赖 Siege、绘图编译器、Rapier 或识别服务。涂鸦攻城同样使用主项目的 Web、桌面和后端入口。协议与规则留在 core，DOM、画布和音频留在 views，框架 API 留在宿主。

```ts
import { PLAYER_TANK, TANK_LEVELS, TankDefenseGame } from "@auro/core/tank-defense";

const customTank = {
  ...PLAYER_TANK,
  id: "guardian-blue",
  speed: 90,             // World units per second
  armor: 2,             // Hit points
  projectileSpeed: 280,
  fireInterval: 22,     // Ticks at 60 Hz
};
const game = new TankDefenseGame(TANK_LEVELS[0]!, { playerBlueprint: customTank });
game.start();
game.setInput("up", true);
// Alternatively: new TankDefenseGame(TANK_LEVELS[3]!, { mode: "blitz" });
game.step();            // Host advances the fixed 60 Hz simulation
const state = game.snapshot();
```

这是本地 TypeScript 接口；开局复制蓝图属性，外部编辑不会改变进行中的战斗。经典坦克的角色库、HTTP API、MCP 和固定版本对局已实现，外部 Agent 的接入与案例见 [坦克角色 MCP](tank-character-mcp.md)。原 [ground2d 自由拼装规范](character-game-api.md) 仍是独立的通用设计，不能与已实现的 `tank-defense@1` 混用。

```sh
pnpm --filter @auro/core exec vitest run tank-defense paths
pnpm --filter @auro/views exec vitest run tank-defense layout search/search-command.test.tsx locales/parity.test.ts

```

浏览器套件使用主站 `TestApiClient` 创建并清理隔离工作区，验证侧栏直接进入、标题与选中态、刷新、真实工作区切换、记录隔离、键盘射击和暂停，以及窄屏触屏操作和内容区滚动。测试不依赖 Siege fixture 模式。开发服务器首次编译路由可能较慢，首次侧栏导航允许 45 秒。

核心测试覆盖碰撞、射击、基地失守、生命与重生、补给可达性、六图入口及机关位置、敌军对无人防守基地的压力、三种模式的胜负、休整、暂停计时、机关相互作用和旧进度读取。页面测试覆盖账号 / 工作区切换、本机存储不可用、身份未解析、街机地图选择和暂停中结束本局。窄屏浏览器测试不代表原生 Mobile 客户端或真实手机验收。

本次难度与全屏验收：core 的坦克 / 路径测试 139 项、views 的坦克 / 布局 / 搜索 / 语言检查 377 项通过；core、共享页面、Web、桌面渲染层类型检查及坦克模块 ESLint 通过。Go 的坦克与 CLI 测试通过，数据库测试使用已登记环境的隔离 fixture。浏览器覆盖原有入口、操控、记录、三种模式、MCP 角色与冻结版本，以及新增的难度保存、原生全屏、退出暂停、手机横竖屏操作。

地图压力测试覆盖六张图各五个固定随机种子，不代表真实玩家胜率。原生桌面安装包与 Mobile 未运行；生产构建未重跑，以免干扰正在使用的开发服务；未部署生产环境。

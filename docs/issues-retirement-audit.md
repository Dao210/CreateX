# Issues 模块退役验收

状态：已完成，2026-11-03。本记录覆盖当前检出与本地 `createx-440` 环境；后续线上重建见[线上基线重建验收](evidence/createx-baseline-rebuild-2026-11-03.md)。

## 退役边界

- Web、Desktop、Mobile 移除 Issues、Projects、My Issues、Squads 页面、导航、设置及任务前缀。旧 slug 继续保留，旧持久化目的地直接丢弃；世界入口为 `/{slug}/me`，旧路由返回 404。
- 删除旧任务 HTTP/CLI、项目与小队、评论与订阅、任务唤醒、PR 镜像和搜索索引链路。附件、编辑器、权限、日期等仍被使用的能力归回独立模块。
- 聊天和自动化保留内部执行队列；它表示智能体执行记录，不再对应用户可管理的 Issue。自动化仅支持 agent + `run_only`。
- 插件删除 Issue 面板、Issue/评论 API、权限和事件，保留上下文、存储、运行事件、Hook、MCP。旧示例、内置引导、快捷开始、运行时指南和 CLI 文案同步清理。
- 移动端删除闲置的评论编辑器、提及与回复辅助链路及中英文文案。聊天附件仍支持上传、预览、重试和消息绑定。
- 企业微信通知按消息 ID 去重，使用 `/inbox?item={id}` 打开详情；不再依赖旧任务 ID。缺少消息 ID 的通知不会发送。
- 收件箱 HTTP/realtime 响应中的旧 Issue 字段固定为空，以遵守仓库的已安装客户端响应兼容规则；数据库、客户端状态及内部业务没有对应模型或兼容分支。历史发布记录作为历史内容保留。

## 数据与迁移

迁移历史改为空库初始化的当前应用基线：104 个业务表，加 `schema_migrations` 共 105 表，323 条迁移。并发索引各自独立迁移，无外键、级联或自动执行旧历史的路径。旧迁移账本会被明确拒绝。

无外键场景下的关系验证和删除由应用事务负责，已覆盖世界删除、聊天消息和附件、构建器会话、运行时解绑，以及执行记录的关联清理；并发写入通过所有者行锁保护。
